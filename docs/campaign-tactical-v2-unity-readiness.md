## Serialization: representable shape, absent complete-root host

[CampaignHost](../client/HobbyDS9.Unity/Assets/HobbyDS9/Runtime/CampaignHost.cs) uses pinned Unity Newtonsoft package **3.2.1**, not JsonUtility. Settings: unknown-member errors, no CLR type-name metadata, maximum depth 128, and required non-nullable scalar properties for Contracts types. Its load/summary path is nevertheless statically typed to **`SaveEnvelopeDto`**, not the physical root.

Minimal integration mismatch, **not executed here**: `CampaignHost.LoadJson(physicalFormat2Json)` encounters the unknown top-level `FormatVersion` member under its error policy. Extracting `Core.Campaign` to bypass this loses the authoritative physical phase, requests, pools/history, contacts/orders and proof. It is not a supported conversion. Existing v1 code is correct for its own contract; it needs a separate review host, not blanket modification.

| Physical root feature | Existing serializer shape assessment / required proof |
| --- | --- |
| Public get/set DTOs, nested `List<T>` in Core/battles/commitments/reports and movement proof | Newtonsoft can represent these concrete DTO shapes; there is no runtime dictionary or polymorphic engine object to serialize. Actual complete-root roundtrip → backend Load → continued outcome is **unverified in Unity**. |
| Int64 progress/cost/revisions, nullable UInt64 RNG, enum values and nullable ingress facts | Keep numeric values exact in C#; no JavaScript/double or UI-string intermediary. Test Int64/UInt64 limits, enum zero versus missing, nullable zero/false versus null and invalid enum rejection. |
| Stop-time numerator/denominator | Persisted as invariant strings, not serialized BigInteger. Validate normalized fractions through the backend on load. |
| `MovementProof` null before first movement; thereafter Start GameState, orders and contacts | Preserve null and complete nested data; no root flattening or omission. Planning, pending, half-committed, resolved and finalized roots need roundtrip cases. |
| Required fields / parser semantics | Existing resolver catches missing non-nullable scalar fields; nullable/list/string requirements still need backend validation. Do not assume equivalence to #28's System.Text.Json case/numeric/unknown-member settings. Add negative tests for missing fields, names/casing, wrong numeric tokens, null rows and corruption. |

A Unity adapter must deserialize **`CampaignTacticalTravelSaveDto`**, then call the actual physical factory before replacing a live session. Serialize only the private host carrier, never `ReviewFrame` or renderer text. The codec interface copies package/save objects; it does not supply the resource loader. Load exact LF bytes of outer package, core manifest and scenario; reproduce the [existing composite hashes](../src/HobbyDS9.Headless/CampaignPhysicalTravelWalkthrough.cs) with Unity-compatible `SHA256.Create/ComputeHash`, not a reserialized JSON hash or the net10 reader.

[SaveSlotStore](../client/HobbyDS9.Unity/Assets/HobbyDS9/Runtime/SaveSlotStore.cs) provides three v1 `campaign-N.json` slots, UTF-8 write/flush and same-directory replace. It can store strings, but supplies neither physical typing nor a format-2 namespace/protocol. Do not reuse `CampaignSaves` filenames or treat this as certified #28 durability. Use a disjoint review directory/prefix, bounded slots, overwrite confirmation and retain-old-on-failure semantics; native file behavior needs its own acceptance.

## Explicit entry, exit and feature-gate composition

- `ClientEntry.Bootstrap` runs **BeforeSceneLoad**, creates a persistent default ClientEntry and applies VSync. OnEnable starts v1 from `ds9-slice`, constructs the old CombatOrchestrator and pumps it. A new scene alone does not suppress this bootstrap. Do not disable/re-enable ClientEntry as panel navigation: OnEnable creates a fresh CampaignHost. Choose an explicit review-only launch/build selector or a deliberately isolated panel route; preserve default false behavior and avoid two clients/input trees. This requires a small coordinated bootstrap seam, not a Simulation change.
- Dedicated review composition: resource/identity loader → Unity codec/store → `PhysicalReviewHost` → `ReviewController` → actor-safe shell/widgets. Keep “review/proposed/activation disabled” visible. Source profiles currently script multiple human actors; show explicit controlled actor workflow or separately reviewed AI source, never silently invent opponent orders.
- Dispatch `Confirm…` work explicitly through the host and deliver its exact receipt to the controller. Painting/refreshing must not commit, finalize, advance a turn or retry rejected work. Pending/dirty exit and overwrite decisions remain explicit. Panel disable/reopen must unsubscribe callbacks, preserve accepted authoritative state and reject obsolete host-generation work.
- Slot load/reopen stages the complete candidate before replacement; unsent drafts remain local and successful replacement clears them. Render only frames and scoped reports, never private roots. Persisted format/profile gates remain closed to default v1; a separate scene/panel is not production activation.
- Current [Windows builder](../client/HobbyDS9.Unity/Assets/HobbyDS9/Editor/ClientBuild.cs) pins 6000.6.5f1, NET_Standard, IL2CPP and **only SampleScene**. A review build needs an explicit scene/build entry; its files/output must not overwrite accepted default evidence.
