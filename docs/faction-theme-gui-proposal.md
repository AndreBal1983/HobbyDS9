## Explicit input and immutable output

`FactionThemeTokens.TryParse(themeJson, catalogueAuditJson, out tokens, out error)` accepts caller-supplied strings only, with a 65,536-character bound on each and maximum JSON depth16. It rejects duplicate keys, comments, unquoted/single-quoted strings, trailing content, unsupported schema/status, extra theme properties, invalid types/colors/ranges, missing profiles, contradictory per-profile audit bindings, shared semantic changes, reduced-motion/flashing violations and audio activation. Body and secondary text require at least4.5:1 contrast against each profile's three surfaces; state text requires4.5:1 against its sample surface. Invalid input returns false and no token object; it does not partially accept a branded theme or activate any fallback file/provider.

The parser checks the matching audit pin, copies scalar values and collections into immutable objects/read-only collection copies, and retains `ArtifactStatus=proposed-design-no-default-activation`, catalogue status and source status. It discards the mutable JSON trees. No Resources lookup, JSON package addition, file access, asset rehash, campaign/private root or provider is required by the parser. The caller chooses the trusted authoring assets. Audit data validates presentation mappings, never gameplay admission or authorization.

`FactionThemeIdentity` requires an explicit identity kind (`Civilization` or `Minor`), stable definition ID and lawful-disclosure assertion. `Resolve(identity)` uses ordinal exact lookup only when disclosed; undisclosed, null, unknown, custom, wrong-kind and unknown-enum values resolve to neutral. The flag is a caller contract, not proof of disclosure. A future integration must pass an already lawfully disclosed public identity or selected own identity, never hidden actor/root IDs or inference from names, species, ship models, audio or thumbnails. Manual local interface preference and observed opponent identity are separate concepts.

The actual Art audit maps exactly Federation/Cardassian/Dominion to three civilization definitions and Ilex/Namar to two independent-minor definitions. Those bindings come from the supplied audit and theme arrays. They are not a new hard-coded gameplay admission rule. Klingon/Romulan arrays are empty. `PreviewProfile("klingon")` and `PreviewProfile("romulan")` allow explicit inspection of proposed style profiles while setting `IsProfilePreview=true`; they cannot create a civilization or make an unknown opponent known. Unknown preview IDs use neutral and remain labelled preview.

## Disconnected Unity sample

`FactionThemeSample.ForIdentity(tokens, identity, reducedMotion=true)` constructs a labelled lawful-binding reference; `ForProfilePreview(tokens, profileId, reducedMotion=true)` constructs a separately labelled manual-profile reference. Both apply inline styles only inside their newly created root. Neither changes its parent, global styles, existing menus or construction widgets. No existing runtime caller instantiates the sample. The parent-owned portable compiler exclusion keeps this Unity-only source outside the portable adapter.

Family chrome draws six distinct geometries from the validated frame/corner/cut/motif tokens: asymmetric elbow/segmented rail, stepped angular brackets, layered curved junctions, swept open spines, interlocked faceted ribs and plain rules. Ilex/Namar use the neutral geometry with their proposed palettes. This is a bounded procedural reference drawing, not a replacement art/style-guide packet or a universal LCARS recolor.

Every sample preserves the eight shared state labels, colors and independently drawn shapes: check, clock, double check, warning triangle, cross, information symbol, unknown dash and unavailable bar. Reference buttons have at least44px height, common navigation ordering, inherited project sans, readable body/secondary sizes and no action callbacks. The sample remains static and silent; its reduced-motion flag exposes a zero transition duration and there is no auto-rotation, flashing, audio binding or gameplay submission. It labels proposal status/source limitations visibly. No actual ship/music selection, networking/database activation, authorization or save behavior is connected.
