## What the compiler/portable harness actually covers

[Portable adapter](../prototypes/HobbyDS9.UnityReviewAdapter/HobbyDS9.UnityReviewAdapter.csproj) compiles the actual six non-engine runtime files by links, **excluding ReviewEntry**. There is no substitute codec/model; it does not shadow engine-facing source with mocks. Its 43 cases cover actual root resume, numeric/shape failures, slots and model/controller behavior, not rendering or bootstrap.

[Compiler-only API project](../prototypes/HobbyDS9.UnityReviewApiCompile/HobbyDS9.UnityReviewApiCompile.csproj) includes all seven review runtime files and ReviewBuild; authored EditMode source is conditional on supplying UnityNUnitPath. It references every DLL in the installed Managed/UnityEngine directory (which contains UnityEditor modules), pinned Newtonsoft and optional Unity-custom NUnit. This broad single .NET assembly does **not** exercise Unity's split asmdefs, import or assembly-qualified bootstrap dispatch. **ClientEntry is absent from it.**

The project/default props do not explicitly define UNITY_EDITOR or UNITY_INCLUDE_TESTS. The inspected linked files have no preprocessor branches, so their bodies are not silently elided; ReviewBuild is compiled unconditionally. This does not certify Editor symbol-dependent assembly inclusion or test discovery. Five authored NUnit cases mean two tests plus three write-stage cases; none is newly executed here. The report's compiler evidence remains narrower than Editor acceptance.
