# Host repository B1/B2 isolated candidate

Authorized by [the implementation brief](design/state-repository-implementation-authorization-20261122.md), based on0fb1405 (ADR55a0c67). No production/default/Unity or portable game project changes. Runtime integration must retain the separate tested2fc0dbc Format18/package5 carrier. Architecture owns integration and native/provider gates.

## Implemented boundary

`HobbyDS9.Persistence` is provider-free netstandard2.1/C#9. It exposes defensively owned `CheckpointImage`, complete opaque `EditionIdentity` (16KiB characters maximum), source turn/revision/phase, request/CAS/reference types and durable receipts. `ICheckpointValidator` is supplied by the trusted host: decode with the matching complete carrier/package, load/replay and compare exact reexport bytes, derive the descriptor/stamp, or reject. Repository metadata is never gameplay authority. The repository checks that returned bytes/hash/descriptor/stamp equal the request; it owns neither simulation state nor a gameplay-format converter.

`HobbyDS9.Persistence.Sqlite` stores full immutable blobs and metadata per campaign; no entity SQL, chunks or live-session queries. A lifetime `FileShare.None` writer handle is held at `writer.lock`, plus an object gate and immediate SQLite transactions. Cooperating hosts must all use this lease. This is not protection against arbitrary programs writing SQL or hostile filesystem replacement. Paths must be absolute, confined to an explicit campaign directory, and free of existing reparse ancestors/targets. Names are bounded Unicode data; IDs are restricted host tokens. SQL parameters carry values.

Storage schema 3 and its application ID are separate from gameplay formats. Unknown schema, edition or campaign is rejected. Trial schemas 1 and 2 require explicit `allowStorageUpgrade` and a verified online backup at the source version before any schema changes. Schema 1 adds the reference timestamp column and the quarantine table. Schema 2 adds only the quarantine table. Failed backup verification leaves the source database at its original schema. A transaction failure retains the backup and rolls back the schema changes. After an ambiguous commit acknowledgment, reopen to identify the committed schema. Payload formats and edition identities remain as recorded. WAL/FULL, foreign keys, a one-second busy timeout and automatic WAL checkpointing are explicit. Payload type and size and text bounds are checked before materialization. Fingerprints use strict UTF-8 and length-framed fields, including source epoch, target identities, stamps, expected generations and every reference/image field.

Commit inserts the payload, moves branch head, updates the requested reference and records its immutable operation fingerprint/receipt in one transaction. Receipt lookup precedes stale CAS on identical retries. Reusing an operation ID with changed semantics rejects; fork/set/delete are similarly idempotent. A commit/acknowledgment exception is `OutcomeUnknown`, not proof of rollback. Reopen and `FindOperation` before retrying; lookup errors never mean confirmed absence. Receipts do not expire during retention.

References support Manual/Auto/Milestone, duplicate names, rename/replace by expected generation and confirmed deletion; deleted IDs remain tombstones and cannot be resurrected with generation0. Forking an older checkpoint creates an independent branch without erasing the original future. Listing is bounded and cursor-based.

Listing includes source turn/revision/phase, storage sequence, reference `UpdatedUtc` and stored payload-availability, without payload decoding or game validation. UI must mark metadata health Unvalidated; a row is not a valid-game receipt. Schema1 references keep an empty historical UpdatedUtc after upgrade; no modification date is invented. `GetStorageUsage` separates live logical payload, automatic and protected bytes, physical DB and WAL bytes. Automatic/protected categories overlap for an active head not manually pinned; manual data is excluded from the automatic soft-budget count. Reading a usage warning never deletes data.

`CheckpointBranchId` reports the checkpoint's stored creation branch, never an assumed active branch. `QueryReferences(ReferenceQuery)` provides exact case-sensitive Unicode name-contains, kind/creation-branch filters and newest UpdatedUtc/ordinal-ID pagination with at most500 rows. `ReferencePage` exposes HasMore/Next, not an invented total count. The cursor is bound to query fields/page size and the repository catalogue sequence; any intervening mutation returns Conflict so the caller restarts rather than mixing generations. Metadata-only queries never deserialize payloads. The simpler original ListReferences ID cursor remains available. Run repository I/O asynchronously through the host: an exclusive in-flight commit/validation can still occupy the repository gate.

Explicit JSON import validates exact bytes before DB mutation, keeps the source read-only/unchanged, creates a verified digest-named recovery copy and stable per-edition/digest operation/branch/manual reference. Repeat import is idempotent while the original protected reference and validated payload remain usable. A deleted/expired import returns Unavailable; a corrupt retained payload rejects validation. The historical receipt remains queryable but does not prove current import usability. Restoring a deleted import requires a separate explicit recovery action; this API never silently resurrects it. Export revalidates then atomically writes exact carrier bytes into an owned exports directory. Backup uses SQLite's backup API, then quick-checks and validates every retained payload before flushing/publishing the destination; copying an open main file alone is not used. Unsupported formats are the matching validator's responsibility; no guessed defaults or14→18 conversion exists.

Explicit post-commit retention defaults to10rolling/3milestones/512MiB soft logical automatic bytes. All manual refs and the active head stay pinned. Old automatic refs expire with generation bumps; unpinned full payloads are removed while ancestry metadata and operation receipts remain. Inactive branch heads can reference an unavailable tombstone, reported explicitly on read, rather than pinning every automatic future forever. This is storage payload GC, not gameplay journal compaction. Physical SQLite pages/WAL may remain larger than logical live bytes; idle checkpoint/space reporting and user-visible budget warnings remain integration work. No autosave scheduler/UI activation is supplied here.

Retention verifies the active replacement's bounded bytes, hash, matching host loader and metadata under the repository gate before opening a write transaction. The immediate transaction rechecks the branch head and generation plus the verified checkpoint bytes, hash and metadata before pruning. A corrupt, invalid, unavailable or changed replacement aborts maintenance without changing references or deleting payloads. If the read proves corruption, it can also record quarantine. Run full host validation on the worker outside the SQLite write transaction.

Reading a checkpoint with definite stored integrity failure, a verified stamp mismatch or an explicit `InvalidCheckpointPayloadException` durably records quarantine before returning `Corrupt`. Emit the typed exception only when the available matching validator has positively identified invalid payload bytes. Cancellation, unavailable content or edition and generic or transient validator failures do not create quarantine. The marker and catalogue sequence advance in one transaction. Repeated reads return the existing status without changing the marker. The original checkpoint row holds the evidence. A separate pin keeps it protected when automatic reference expiry or recovery on another branch removes it from the ordinary save list.

`SaveReference.Quarantined` projects the durable status for any reference that remains visible. The optional `IQuarantinedCheckpointRepository` capability lists quarantined checkpoint IDs, detection time, classification and observed payload size/hash even after their references expire. `RepositoryUsage.QuarantinedPayloadBytes` counts those payloads under protected storage. Quarantine uses no rolling slots or automatic budget. Evidence export verifies the hash of the actual observed bytes and exclusively writes a new `.bin` in the owned `quarantine-exports` directory. Missing or out-of-bounds evidence reports `Unavailable`. Export keeps the evidence pinned. General backups verify safe quarantined evidence against its observed metadata rather than attempting to load it as a game.

Quarantine writes can fail. A failed or uncertain pin returns the storage error and blocks retention on the open repository until the failed checkpoint is rechecked and the pin confirmed. Across restart, a committed marker remains in force. If the previous attempt failed without committing, the host must recheck that checkpoint before re-enabling retention. Backup verification still fails closed for structurally damaged databases or unverifiable legacy schemas. A disposal or repair operation is outside this recovery change.
