# SCIENCE-AUTOAPPLY-01 GUI candidate

15 November 2026. Source candidate; native input/layout acceptance pending. This owner-approved workflow supersedes historical Research preview/Apply instructions in the [foundation](science-engineering-v1.md) and its [local acceptance record](science-engineering-v1-local-acceptance.md). It changes presentation and command admission, without changing simulation research arithmetic, save formats, catalogue access or publication validation.

Science bars preview locally while dragging. The complete six-share plan commits on pointer release or committed keyboard/step change. Escape/capture cancellation restores the preview. All six live labels rebalance to exactly 100%, with exact weights totalling 600 and locked shares retained. The shared Science/Engineering split previews locally during a pointer drag and commits on release; keyboard changes commit directly. Equalize unlocked uses the same direct authoritative path. Apply Science allocation, Apply R&D split and Restore accepted shares are removed, including footer Apply/discard routing for these controls.

Committed input queues the latest complete plan for each allocation layer. A 20ms owning-thread UI drain coalesces a rapid burst and serializes the existing stamped commands. If both layers changed, the second uses the accepted first command's new stamp. An unchanged final value submits no command. Stale/busy/rejected work restores accepted values, shows local feedback and stops; there is no automatic stale retry. If the first layer was accepted and the second rejects, the accepted first layer remains authoritative. Session replacement cancels the old queue; delayed callbacks are bound to the owning model. Disable cancels pending input. Allocation refresh retains the panel and restores scroll/focus after layout.

Pending commits briefly guard End turn until acceptance. Accepted allocations leave no persistent dirty/discard barrier. Unsent travel/combat/organization orders retain their existing guard. The unpublished Ship Designer draft is excluded from Planning barriers in the footer, shared combat flow and synchronous/Colonisation/streamed advance paths. It stays editable across navigation and turn refresh because the existing designer state remains bound to the same controller. No advance path publishes a blueprint, overwrites a revision, refits a ship or adds construction.

Draft persistence is **session-only**. Saving the campaign retains the in-memory draft while writing accepted campaign state; it does not serialize that unpublished fit. The UI says so. Loading/replacing the session, switching actor and quitting retain explicit discard protection. Publish still requires explicit action, current catalogue/stamps and portable fit validation; after a turn, Refresh campaign revalidates while retaining the fit. Invalid drafts remain editable and unpublishable. Durable draft persistence would need a separate versioned draft workspace/storage seam; this candidate does not claim it exists.
