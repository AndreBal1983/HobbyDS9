# PB-20261113 content byte compatibility

13 November 2026. Data candidate based on GUI `686e213dd78b2151446ae994ead69d3a48838555` (PR89). This fixes checkout and adapter input policy; no gameplay or save schema changes.

## Established policy

[Architecture](architecture.md) assigns exact-byte content hashing to the host and requires matching identities on load. Scenario JSON is LF under the original root `.gitattributes`. Preparation copies those bytes directly, without parsing or rewriting. The retained Demo, Frontier, Integrated and Review resource directories lacked matching attributes, so Windows `core.autocrlf=true` changed their checkout bytes. Explicit LF attributes now preserve all prepared package copies, including the two default resource copies.

Colonisation is a historical exception: commit `f7fdca3f4f2bd39ddd0f8ca193bfb4a15b37e5e3` introduced `ColonisationPlaytestOptions` with four exact CRLF resource hashes. Roster V2 later added a fifth CRLF resource hash. These are composition-root asset pins independent of save metadata. The portable authoring sources are LF; the composition assets are the same text encoded with CRLF. Explicit CRLF attributes preserve the historical assets on every host, including Linux/macOS. Adapter tests now copy those Unity assets into their composition input directory; separate LF authoring inputs prove that both decode to the same existing `PackageHash`. No hashes, decoder rules, save identities or source manifests are rebaselined. Arbitrary whitespace and alternate newline encodings still fail composition validation.

## Regression and receiving

`ContentByteCompatibilityTests` compares every authoring/resource pair, checks equal package identity, and rejects LF reencoding or appended whitespace independently for each asset. Existing adapter cases exercise complete load, replay, rollback and draft preservation using the actual pinned assets.

Run `python scripts/check-content-resource-bytes.py --checkout-matrix` from a committed checkout. It checks 27 prepared resource pairs and five historical pins, then exercises committed Git extraction under `core.autocrlf=true`, `false` and `input` using temporary private indexes. The adapter CI workflow runs it across Linux, Windows and macOS. The checker does not repair inputs or rewrite hashes.

Receiving QA must use a fresh checkout of the committed candidate or explicitly refresh only the resource files covered by these attributes before preparation; changing attributes does not rewrite an already populated worktree. Do not reuse the GUI worktree's prepared files as source evidence. Run `dotnet msbuild scripts/PrepareUnityGeneratedGalaxy.proj -t:Prepare`, then the byte checker, and verify that preparation leaves no tracked diff. Existing saves continue through their original explicit profile loaders; no conversion or fallback is added. Backend owns the separate generation timing failures. Native/Editor/AOT acceptance remains QA's gate.
