# Generated v2 background checkpoints — source candidate

24 October 2026. This increment applies only to the explicit static-astronomy v2 player Save/Load controls. Existing synchronous APIs, v1, other profiles, ingress validation and custom-codec chains are unchanged. Source/CPU checks do not establish actual Unity or native responsiveness.

## Typed ownership boundary

`PhysicalReviewHost.PrepareStaticCheckpointSave(observed, slot, overwrite)` captures an already-detached portable authoritative export and status under the live host gate, validating host/generation/turn/revision. It returns opaque, one-use `StaticCheckpointSaveWork`. Its worker-only `Execute(cancelled)` performs the first closed-codec copy, the same complete authoritative replay validation (including the optional owned-export capability), then the unchanged typed store write outside that gate. The new path requires explicit `IBackgroundStaticCheckpointCodec` and `IBackgroundStaticCheckpointStore` opt-ins; the production participants are the sealed stateless codec and internally locked typed v2 store. Existing custom interfaces alone do not opt in. No root/template is exposed in the player presentation. Brief source-stamp checks occur before validation and before writing; no long replay, JSON work or IO holds the live host gate. Capture itself still costs a bounded full detached export and is measured separately; this is not zero-cost asynchronous capture.

`ReviewUiModel.BeginStaticCheckpointOperation` is UI-thread owned: it refuses busy/closed/pending state, captures the controller/frame, and requires explicit discard for loading dirty drafts. `ReviewCheckpointOperation.Execute` is the only worker entry. It does not change the live model or controller. Load uses the explicit v2 candidate opener, building the candidate controller and matching known presentation before returning an opaque completion. `CompleteStaticCheckpointOperation` is UI-thread owned and publishes only for the same active lease, controller, exact frame and live source stamps. Loading replaces both model host and controller together and clears drafts only after every candidate failure point. Save completion records the result without replacing the frame/drafts. `AbandonStaticCheckpointOperation` invalidates publication and releases the model busy flag; a stale completion cannot unlock a newer lease.

The Unity caller additionally captures its model and view epoch. While busy it replaces interactive content with status, detaches map schedulers/renderers through the normal content lifecycle, and preserves the original drafts in the model. The UI dispatcher remains free. Disable invalidates the lease; renderer current-observation callbacks cannot wait on replay holding the host gate. Resize/view replacement may invalidate publication; a stale result never replaces newer UI state.

Cancellation before the final write check prevents writing. Once the atomic store write has begun it may complete despite subsequent teardown: cancellation is not a rollback of a durable save. A save denotes the accepted snapshot captured at invocation, excluding local unsent edits. The unchanged store rechecks confinement/type/size and overwrite races, flushes its temporary file and atomically moves/replaces. An empty advisory probe never authorizes overwrite. Worker errors are mapped without publishing private diagnostics. No trusted-file cache, validation skipping, conversion, regeneration or alternate save schema is introduced.

## Acceptance to establish

CPU checks must block the worker inside validation/IO and demonstrate live host reads and old presentation validation remain available; verify one-use work, busy/pending/dirty refusals, stale/abandoned completion, immutable captured slot, late invalid-load failure, full draft/frame preservation, atomic raced writes and exact synchronous/background bytes. Record detached capture duration separately. Player/Editor reference compilation and metadata checks precede a separately authorized actual UI case; no import, GPU, native player or owner-data work is authorized by this document.

The first focused source run passed 24 cases: 11 new background-operation cases and 13 existing owned-export regression cases. Captured 250/1000-system exports took 2.201/4.143 ms in that CPU run; these are observations, not UI/hardware guarantees or hard latency budgets. Full copy, replay and writing remain additional worker work. Player and Editor runtime reference builds had zero warnings/errors; the unchanged receiving test source `DemoRuntimeAcceptanceTests.cs:69` produced one nullable warning in the Tests reference build, with zero errors. Actual Unity/background-busy presentation, frame pumping, lifecycle and native acceptance remain unverified.
