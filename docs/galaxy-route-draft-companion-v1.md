# Map-review route-draft companion v1

Status: scoped host implementation, pending engine/native acceptance. No campaign/save/order changes.

The route panel offers explicit **Save route draft** and **Restore route draft**, using the currently selected map-slot number. Companion files live in the separate `HobbyDS9GeneratedGalaxyRouteDrafts-v1` persistent directory, outside the existing map-review namespace. The bounded atomic host file writer retains its historical `generated-map-N.json` slot filenames inside that new directory; these are route-draft documents, never generated-map exports. Map export and companion save are independent operations, never advertised as one transaction. Replacement of an existing companion requires explicit confirmation.

Wire version1 admits exactly FormatVersion, MapContentHash, PolicyVersion, Start and ordered Targets. Each anchor contains NodeId and Kind (0 region transit,1 star location), neither of which orders a visit/scout action. Hash is64 lowercase hexadecimal characters, identifiers use canonical ASCII form up to128 characters, target count is at most64 including final, and read/write payload size is at most32KiB. Duplicate, extra, missing or wrongly typed properties reject. No current filter/authorization, route result, cost or generated geography is persisted.

Restore decodes into detached state, requires the current map hash and supported route policy, checks the start's region/location association, then submits all ordered legs to the portable FindRoutePlan with a freshly supplied current filter. Full-map review explicitly supplies all current navigation IDs; this is no campaign authorization provider. A start-only draft validates the origin/filter with a real zero-crossing query, then retains an empty target list. Any malformed/stale/wrong-map/blocked/unavailable result leaves the live queue, current plan, map and export unchanged. Successful restoration publishes the entire validated draft/plan together. Repeated targets and backtracking remain distinct anchored legs.

The existing file writer gains only an optional smaller byte ceiling, defaulting to its unchanged map-export limit. Pre-existing map slots and namespaces are untouched. Fault injection covers interrupted companion overwrite with prior bytes retained and temporary payload removed. Original test failure from generic physical-codec admission of a host-only DTO is retained in evidence; decoding now constructs this explicitly shaped host DTO directly, preserving the physical codec's Contracts-only restriction.

Successful format4 Open also updates the large-map model selector; successful legacy/scaled Open clears that selector, and failed Open keeps the user's current selector. This closes an independently reported host state inconsistency without changing generated map bytes.
