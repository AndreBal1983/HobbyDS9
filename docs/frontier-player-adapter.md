CPU-only binding from R7 source `6412ca74`. The [frontier backend](frontier-reconnaissance-v1.md), [host seam](frontier-review-client-seam.md) and [strict JSON/disk adapters](frontier-review-persistence.md) already own gameplay and complete wrapper5 persistence. This increment only connects the real player model and exact resource assembly. It does not replace the validated Bajor demo or implement a full 4X game.

## Public integration contract

`ReviewUiModel(CampaignFrontierPackageDto package, ReviewNewtonsoftCodec codec, ReviewFrontierSlotStore slots)` derives exactly one persisted Human civilization from the assembled package; actual `PhysicalReviewHost.StartFrontier`/controller validation remains authoritative. Missing or ambiguous human selection rejects construction. `FrontierPreview` identifies this profile, `Integrated` is true, and `SingleplayerDemo` remains exclusive to wrapper4. `SwitchActor` cannot select another actor in this preview. Use `Current.Frame.Actor`, actor-filtered `Current.Frame.Frontier` and existing known `Strategy.Navigation`, never private package/state/transcript facts for rendering.

Existing model travel APIs (`DraftTravel`/`SendTravel`, `SendPreviewedTravel`), `Advance`, round commitment and explicit `FinalizeBatch` use the existing authoritative host/controller. `Save` and `Load` dispatch complete wrapper5 first. Model Load opens a fully validated candidate before replacing both its cached host and controller; failures retain existing frame/host/generation and local travel/research/design edits. Call model Load rather than externally reopening only its exposed controller, which would leave an obsolete cached host pointer.

`ReviewExactPackageLoader.LoadFrontier(byte[] frontier, byte[] integrated, byte[] physical, byte[] core, byte[] scenario, ReviewNewtonsoftCodec codec)` assembles the exact existing nested hash ladder. The outer input names are `frontier.json`, `package.json`, `physical.json`, `core.json`, `scenario.json`; resources belong under `FrontierPackages/v1/`. Its hash prefix is ASCII `campaign-frontier-review-package-v5\n`, followed by lowercase SHA256(raw frontier.json bytes), newline, integrated package hash and newline. No JSON reserialization or newline conversion enters identity.

`scripts/PrepareUnityFrontier.proj -t:Prepare` copies only those five raw source files. `FrontierOutput` overrides the destination for artifact/temp checks; default destination is the calling checkout's `client/HobbyDS9.Unity/Assets/HobbyDS9/Review/Resources/FrontierPackages/v1`. This target deliberately does not call other preparation projects, start Unity, prepare binaries, choose a startup or activate a profile. The eventual builder calls ordinary portable preparation separately. Entry/menu/map/builder and resource folder metadata remain Secondary's separate ownership.

The coordinated frontend injects `ReviewFrontierSlotStore` under `HobbyDS9FrontierPreviewOnly-v5`, using slots `frontier-1`/`frontier-2`/`frontier-3` and `unity-frontier-review-v5-{slot}.json` files. These remain disjoint from default Demo4 Start/Continue1–3. No downgrade/fallback or automatic import is provided.
