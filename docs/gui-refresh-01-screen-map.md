## Existing design and interaction constraints

Use the [LCARS foundation](lcars-ui-foundation-v1.md), [instrument-bank contract](lcars-instrument-bank-v2-acceptance.md), [combat interface](art/combat-interface.md), [battle art handoff](art/playable-battle-art-handoff-2026-10-20.md), and current [System](sys-vis-01-gui.md), [Production](prod-vis-01-gui.md) and [modal](unity-review-modal-permission.md) contracts. Retain the established amber/lavender/dark hierarchy, readable mixed-case data, explicit text states, visible focus, accessible hit targets and bounded content. The accepted first-iteration combat composition is documented; its fictional values and later proposed refinements are not additional gameplay authority.

Current integrated ReviewEntry marks narrow layout at logical width below 1600 or height below 850 ([Geometry](../client/HobbyDS9.Unity/Assets/HobbyDS9/Review/Runtime/ReviewEntry.cs#L219)). The historical LcarsShell's six-section navigation and 1700/Wide policy describe another implementation. Do not blindly apply them to the current twelve-page shell. Art/GUI should reconcile visual intent against actual current geometry rather than treating old token numbers as proof of parity.

Preserve these cross-screen distinctions:

- **Inspection, selection and navigation** versus **local draft** versus **accepted command** versus **resolved result**. None is an implicit substitute for the next.
- **Known now**, **historically observed**, **unknown**, **unavailable** and **empty**. In particular, unknown is never a zero quantity.
- **Actual retained stock** versus **capacity/output**, **bank** versus **new allocation**, and **frozen revision** versus a new design. Rendering or resizing changes none of them.
- Keep the shared scrolling modal body/fixed footer, focus restoration/trap, release-before-next-notice handling and one-use callbacks. Long text and sequential dialogs must not expose background gameplay controls.
- Keep stable IDs, current actor/frame/generation and busy-operation ownership through rebuilds and callbacks. Preserve valid local selections, drafts and scroll/focus; discard only through an existing explicit workflow.

This is a reference gap, not permission to invent replacement artwork or an assertion that the unavailable target was never created. Art's reference register should carry the approval/provenance decisions; this source map does not duplicate that register.
