# Galaxy designer art integration

Source receiving candidate. The actual optimized asset payload, imported textures, final shader output and input/render behavior require separate Unity and executable acceptance. No new paid art generation is part of this work.

## Viewer contract

`ShipDesignerPreview.SetFit(hullVersionId, installedCounts, pendingPreview)` accepts detached presentation facts. Pending candidates are labelled PREVIEW; this API never changes a draft, campaign, compatibility, power or unlock. Exact `hull.utility.v1` maps to an **illustrative** Galaxy reference, not an actual Galaxy-class blueprint or ship identity. Unknown hulls and missing resources retain a labelled schematic fallback. `ShipPreviewStage.Show(ShipPreviewSelection)` and its lawful identity resolver remain separate and unchanged.

The received pack is under `ArtDemo/Designer/Galaxy/Models`, with exact source filenames and material remaps. Its ten selected FBXs total 90,665 resource triangles: GalaxyHull LOD0, GalaxyHullCutaway LOD1, Sovereign nacelle pair LOD0, classic pair LOD1, core LOD0, blue deflector LOD0 and amber/survey deflectors LOD1. The default Sovereign-style illustration draws 75,534 source triangles. One hull or cutaway, one pair, one core and one deflector are instantiated; variants replace their previous instances. This is presentation selection, not propulsion technology or blueprint compatibility.

The shared parent scales 620 metres to ten preview units. Components are socket-relative and receive their translation exactly once: port (-125.6418,-49.131,-214.65), starboard (125.4987,-49.131,-214.65), core (0,-56.286,-64.395), deflector (0,-64.395,75.366); rotation identity and scale one. Both hull variants remain at origin zero. The combined nacelle parent remains zero. Actual native Unity axis/unit interpretation is still a receiving gate.

Only exact `component.propulsion.v1` and `component.reactor.v1` currently bind to representative nacelle/core geometry. Zero removes the representative from the full-hull view; positive counts show one representative and display the actual package count. Multiple packages are not falsely placed in overlapping physical sockets. Other package types retain schematic facts. No catalogue deflector component exists: its fixed hull detail and dedicated art-study view are explicitly **unbound**, never inferred from sensors or claimed as an installed deflector. The internal view hides the hull to expose an art-study core; it is not a structural engineering-room simulation.

The existing 768×480 stage is retained for same-hull edits. Manual orbit buttons and left dragging on `designer-hull-reference-image` rotate its camera; image-only wheel input applies bounded .6–2.2 zoom. Pointer Up, Cancel, capture loss, detach and disposal release capture. No automatic rotation, frame loop, timer or interaction capture outside the image is added. `SetReferenceView` switches Hull/Nacelles/Deflector/CoreCutaway and refits projected bounds. `SetStudyVariant` and labelled ART STUDY controls switch classic/Sovereign nacelles and the three deflector visuals without changing any fit or campaign data. Unknown/missing art is labelled. These source behaviors still need actual input and lifetime tests.

## Materials

The studio shader now samples UV base colour and emission textures, with their source transforms, and tangent-space normal maps when present. Material conversion copies these into private preview materials; shared source materials/textures are unchanged. It retains the controlled studio lighting and scalar metallic/smoothness approximation. It does **not** claim a full glTF metallic/roughness, alpha/transmission or physically matched Blender material renderer. Actual Unity texture orientation, sRGB base colour, linear normal import, tangents, mapping and appearance must be checked from received assets. A source/reference compile cannot validate HLSL output or texture fidelity.

The selected receiving pack supplies four exact 2048² PNG base-colour maps (2,101,346 source bytes), twelve explicit material roles and dedicated emissive submeshes. It supplies **no normal or emission mask textures**; normal capability is therefore dormant. Each FBX metadata file explicitly remaps its named source material roles to the received private assets. Mips and sRGB base-colour import are requested, with non-readable textures and desktop compression. Four fully uncompressed RGBA32 mip chains would be 89,478,480 logical bytes (about 85.33 MiB); actual imported graphics format and footprint must be measured, not inferred from PNG byte size. The private material cache reuses canonical role materials across gallery replacements.

`tools/art/receive_designer_galaxy.py` verifies source bytes against the art delivery manifest, copies only selected FBXs/PNGs/contracts/rights, writes deterministic metadata/material remaps, and records `receiving-inventory.json`. Initial receiving has 35 metadata files inside the Galaxy folder, all GUIDs distinct, plus two parent-folder metadata files. Source-only hash audit found zero mismatches. Repeated extension requires an explicit flag and verifies the prior inventory before adding variants. Neither the original large blend/GLB nor failed/superseded material assignments are imported.
