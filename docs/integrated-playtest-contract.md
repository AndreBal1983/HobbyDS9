## Shared session and proposed API pin

Application exposes `CampaignIntegratedPlaytestApplication.StartPackage(CampaignIntegratedPlaytestPackageDto)` and `LoadSave(CampaignIntegratedPlaytestPackageDto, CampaignIntegratedPlaytestSaveDto)`, returning `ICampaignIntegratedPlaytestSession`. It extends the existing `ICampaignTacticalTravelSession` travel/contact/tactical surface. All panels must retain **the same returned instance**. No parallel default-v1 or fixed-review session is a substitute.

Additive operations:

```csharp
CampaignIntegratedStrategySnapshot CaptureStrategy(string actor);
CampaignIntegratedPlaytestSaveDto ExportIntegratedSave(); // trusted host/store only
```

`CampaignIntegratedStrategySnapshot` lives in Application and contains immutable copied `Status` (`CampaignTacticalReviewStatus`), own `Civilization` (`CivilizationSnapshot`), `Research` (`ResearchOverviewSnapshot`), owned `Colonies`/`Ships`/`Fleets` (existing snapshot types), filtered `Navigation` (`NavigationMapSnapshot`), and `Construction` (`IReadOnlyList<CampaignIntegratedConstructionOption>`). Each construction entry exposes `ColonyId` (EntityId), `Design` (ShipDesignSnapshot), `FitId`, `FitRevision`, `ProvenanceId`, `UnavailableReason` (CommandErrorCode), and `CanEnqueue`. Research retains existing card fields `CanTarget`, `Band`, `Progress`, `Cost`, requirements, six Science cards and receipts. The advisory availability is blocked by the actual physical phase during combat. Renderers receive only these actor projections, own travel/contact views and actor tactical observations, **never a private full save/core/global campaign snapshot**. Uncontrolled/unknown actors reject.

Submit existing observed-stamp `CommandEnvelope` through inherited `SubmitStrategicCommand`: `SetResearchAllocation`, complete six-way `SetScienceAllocation`, `SetEngineeringTarget`, admitted static `EnqueueProduction`, and owned `CancelProduction`. Existing payloads, IDs, 600-unit research arithmetic, fees, industry, eligibility and command validation remain authoritative. Physical routes use inherited `SubmitTravelOrder` / `FindKnownRoute`; tactical commitments and finalization retain the existing physical facade. During combat, strategy views may be inspected but strategic edits are blocked by the authoritative physical root phase.

## Explicit construction admission and compatibility

An additive integrated wrapper declares exact **static design → authored fit/revision/provenance/initial stocks** bindings. Only expressly listed valid existing authored-v2 templates may enqueue. Completion uses normal paid FIFO Industry/ship allocation/join-or-new-fleet construction, then validates and initializes equipment/pools **once** inside the same staged whole-root transaction. No arbitrary immutable v1 designer blueprint conversion, inferred stats, refit, general compiler support or unearned Engineering unlock is authorized. Ordinary unsupported static designs and `EnqueueBlueprintConstruction` remain typed unsupported admission failures. New fleet travel/cloak settings must be initialized coherently in the same transaction.

Integrated package/save wrapper **format 3**, profile `campaign-tactical-v2-integrated-playtest-1`, deliberately encloses the existing physical format-2 root and authored construction binding/provision provenance. Nested B1 format 1 and legacy Save 14 / authored Content 11, rules `science-engineering-v1`, compiler `ship-design-compiler-v1` and existing movement/tactical resolver identities remain unchanged. The wrapper owns new semantics; old bare v1/B1/physical saves are unsupported for this new loader with explicit errors, **no silent wrapping/migration**. Existing profile fixtures/loaders/hashes stay unchanged. The new wrapper persists complete strategy, queue, equipment provenance, stocks, movement, rounds, phase and replay ledgers; never save its nested root alone. Package hash and exact source bindings reject substitution/cross-profile reloads.

Exact ingress DTOs are in [Contracts](../src/HobbyDS9.Contracts/CampaignIntegratedPlaytestContracts.cs). Package has nullable-required `FormatVersion`, `ProfileId`, `PackageHash`, `PolicyStatus`, `DefaultActivationAllowed`, `Physical` (CampaignTacticalTravelPackageDto), and `ConstructionTemplates`. A template carries `ShipDesignDefinitionId` and `SourceProvisionShipId`; the referenced immutable authored provision resolves the exact fit/revision/provenance and initial stocks, rather than accepting invented values from the UI. Save carries `FormatVersion`, `ProfileId`, `PackageHash`, complete `Physical`, and append-only `BuiltShips`. Each built record has `ShipId`, `ShipDesignDefinitionId`, `SourceProvisionShipId`, `OwnerCivilizationId`, `FleetIdAtConstruction`, `QueueItemId`, `TurnBuilt`. Records survive destruction; mutable pools remain in the physical core. Inherited `ExportSave()` deliberately throws for integrated sessions: only `ExportIntegratedSave()` preserves the full contract. This distinction must be implemented in the trusted host/store adapter.

The four raw inputs are `package.json` (outer metadata/templates), `physical.json`, `core.json`, `scenario.json`. Assemble typed Campaign and hashes exactly as [host package reader](../src/HobbyDS9.Headless/IntegratedPlaytestPackageReader.cs): lowercase SHA-256 of raw source bytes; core hash `SHA256(ASCII("campaign-tactical-review-package-v1\n" + SHA256(coreBytes) + "\n" + SHA256(scenarioBytes) + "\n"))`; physical hash `SHA256(ASCII("campaign-physical-review-package-v2\n" + SHA256(physicalBytes) + "\n" + coreHash + "\n"))`; outer hash `SHA256(ASCII("campaign-integrated-playtest-package-v3\n" + SHA256(packageBytes) + "\n" + physicalHash + "\n"))`. Do not normalize resource bytes before hashing. Persist only full format3, and fail closed on unsupported format/profile/package before replacing the live instance.
