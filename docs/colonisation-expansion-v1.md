# Lawful first-expedition AI — portable expansion v1

Status: **candidate portable implementation**, pending exact source review. This is a deliberately small, opt-in planner, not the complete strategic-AI roadmap. No Unity/menu/slot/default activation is included here.

The explicit `CampaignColonisationExpansionPackageDto` wraps the unchanged roster-V2 package and a closed named provisional planner policy. Its complete save is Format12 (`generated-colonisation-expansion-v1`): the complete retained colonisation base plus one fixed goal per actual AI actor. Old V1/V2 entry points and exports remain separate; old-profile exports refuse an expansion session. Loading reconstructs the new planner at genesis, executes it during each recorded Advance, then compares both the entire base and the complete plan state. Hashes and receipt DTOs alone never authorise a save.

Each AI owns at most one first-frontier goal. It chooses real sustainable source population and a real shipyard, streams one transport and settlement kit through the ordinary queue, discovers and surveys only actor-observed bodies, returns and lawfully joins its own co-located ships, embarks 100 people, one physical kit and 20 food, travels, requests deployment, and supports the actual camp. The shared post-combat all-actor settlement census decides the landing. A reused empty carrier can return, load supply-only cargo from actual local stocks and deliver it. Actual shortages can cause evacuation, retained return-only cargo, blocked-return holds and deaths under the existing rules. Completing the first colony does not grant a second colony goal.

Provisional policy: one goal, at most 8 decision/action attempts and 4 accepted mission actions per AI/week, 16 body candidates, 8 route candidates/failed own targets, two bounded actor-known graph traversals (2048 nodes/8192 edges), two weeks of current home food-deficit reserve and voyage contingency, and two disputed-boundary waits. Unsuitable completed own surveys and unsuccessful own landing attempts use the same bounded failed-target memory. Searches use shared effective navigation costs; food forecasts use the actual own-fleet travel projection. Forecasts are not safety guarantees. Terminal/survival handling precedes the discretionary failed-target cap. Only currently needed mission fleets, surveys and production are reserved from the existing scouting/procurement fallback.

Each action uses a further detached transaction and the existing player payload/validation kernels with a private AI-controller gate, exact turn/revision and canonical internal command ID. It increments actual revision once and uses the AI accepted-ID ledger, never a fabricated human journal command. Candidate capacity reserves the enclosing Advance separately. Whole-turn late faults roll back plans, resources, physical state, journals and caches together. Latest receipts are fixed-size; no weekly plan-history log is appended. The aggregate guard reserves 224 visits/96,320 conservative canonical bytes per fixed actor from genesis, plus outer overhead, within the existing 2M/64MiB ceilings. It reserves future full receipts/targets even when current lists are empty.

## New-profile planet-unit correction

The legacy generated variants used gravity/pressure values 80–150 while the actual major-species definitions use 4000–18000 (Earth-like 10000), and `atmosphere.oxygen` instead of the existing `atmosphere.oxygen-nitrogen`. A focused regression preserves that historical defect as evidence. Only the new expansion inventory uses the closed `planetary-inventory-expansion-units-v1` / `expansion-environment-units100-v1` authoring identity: generated gravity/pressure are multiplied by 100; non-vacuum oxygen uses the existing oxygen-nitrogen vocabulary. The same correction applies to generated minor-world physical overrides. Homes and guaranteed home-environment clones, planet/body/system IDs, variant ranks/distribution, classes, radiation, finite deposits and habitat shares/capacities are unchanged. Independent minor population remains in its existing unsimulated domain, not an economic cohort.

Old frozen inventories keep their exact old facts and hashes. Inventory validation requires an explicit expected closed policy (legacy by default); it never selects a policy from the untrusted DTO. New loading checks the exact expected genesis and consumes the retained frozen facts. There is no migration or reinterpretation.

## Evidence boundaries

Tests distinguish the real public 250-system manufacture/survey/loaded/founding/established/supply journey and entire replay from explicitly labelled private planning/failure/arithmetic fixtures. Such fixtures do not prove fabricated histories load. Source acceptance, adapter/codec/host/UI integration, native/IL2CPP behavior, large-map performance and general strategic-AI quality remain separate gates. Existing full-save/replay latency remains an open limitation.
