# Engineering and Science control polish

15 November 2026. Owner corrections supersede the earlier full-width Engineering sections and locked-card inventory preview. Source candidate; native acceptance pending.

New engineering projects is the left column and Technology refinement the right, balanced below the shared accepted-income/bank/current-project summary. Both have independent search, technology selection and vertical lists/scrolling. Normal desktop widths remain side by side; only content widths below 600 stack. Cards wrap their text and do not expand to fill arbitrary horizontal space.

Default lists show authoritative `CanTarget` projects plus retained active/completed work. Source Science and Engineering prerequisites remain the validator; the GUI does not guess from a discipline or breakthrough. Temporarily locked/unavailable work is hidden. The known unsupported Cycle Scout output is not advertised as available; any retained/completed history labels its unavailable construction outcome. Counts update to actual visible/filter results; empty lists say No projects available. Existing Science/Engineering tabs provide navigation; no locked-roadmap toggle or redundant persistent crosslink is added. Available/Active/Completed text is paired with LCARS green/amber/lavender states. Project popups keep actual requirements, progress, costs, stamped commands and one-use modal lifecycle.

Both technology fields use the same owned LCARS selector rather than an OS/native PopupField. It has an explicit selected check and text, dark surfaces, amber focus/selection, wrapped labels, constrained viewport placement and vertical-only scrolling. Up/Down/Home/End/Enter/Escape/Tab navigation, focus return, capture-backed outside dismissal and detach cleanup are handled locally. Opening a standard campaign modal closes the menu first; it introduces no gameplay command or stamp. The immediate Engineering flow has no other native filter menu.

Science allocation locks now use native checked toggles with owned open/closed padlock vector strokes, 44px hit height, tooltips/action labels and visible focus. No emoji/font glyph asset is needed. The native toggle's checked value represents the actual share-lock state; label and tooltip distinguish allocation locking from technology eligibility. The existing local lock/redistribution and exact total semantics remain.

Portable receiving covers actual locked/eligible/active/completed states and all prerequisite gates, not only styling. Updated Unity fixtures check balanced columns/empty visibility, custom menu boundaries/keyboard/outside dismissal and lock state. These are authored and source-compiled; QA still owns actual menu rendering, no horizontal scroll, pointer capture, keyboard/screen-reader behavior and 1280/1920/ultrawide inspection. The earlier HTML inventory preview is historical and is not the current layout/availability contract.
