# Generated save overwrite admission

24 October 2026. A scoped UI responsiveness increment, not a save-format or validation change. Source/CPU verification is separate from actual Unity and packaged-player acceptance. The safe ba943 V2 package remains immutable.

The generated stores offer an optional advisory slot check under their existing store lock. It checks slot confinement, directory and destination type/reparse guards and existence, without creating a directory, encoding a campaign, reading a save or writing bytes. The V2 store adapter forwards the capability only when the original typed store supports it. The optional host seam validates the observed host/generation and current turn/revision before delegation. Pending controller work and closed/busy models refuse the probe. The probe leaves model messages, checkpoint errors and all draft/session state unchanged.

Only a supported occupied result changes the UI path: Save immediately opens the existing one-use replacement confirmation. Cancel performs no export, replay or write. Confirmation captures the requested slot, model, controller and view epoch and invokes the existing Save(true) only while that context is still current. Empty, unsupported and other advisory results use the original Save(false), including its existing error ordering. If a file appears after an empty probe, the final write still refuses replacement and the usual confirmation is offered.

The existing SaveCommittedToSlot, full Export/replay validation, codec copies, final store encoding and atomic Write implementations are unchanged. Admission is never cached or used as permission to write. An occupied destination with an unserializable campaign still returns the original SerializationFailed from a direct Save; the new advisory result is not reported as a completed save. This removes the first expensive validation from the common overwrite-prompt path; the actual confirmed save is still synchronous and can block the UI.

Focused CPU checks cover no-directory/no-encode admission, traversal rejection, invalid-root error precedence, raced-file preservation, exact V1/V2 namespace separation, unchanged draft/frame/message/checkpoint error, closed/pending/stale refusal and unsupported typed stores, alongside existing complete-root and interrupted-write tests. Actual Unity receiving must additionally exercise occupied prompt/Cancel through the real UI, context guards and confirmation saving; reference compilation does not establish UI timing or native acceptance.
