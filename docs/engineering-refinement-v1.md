## Scope and provisional policy

Format17 (`generated-engineering-refinement-v1`) is an explicit peer of the previous Cycle editions. It includes the authored Sol belt generation and opts into reactor refinement support v5. Earlier campaign/save identities remain closed. Start a new campaign in the separate `-engineering-refinement-v1` directory. Previous saves remain for their original executable; there is no migration.

The two supported authored baseline reactor families/roots are the authored Reactor and Compact Reactor. Baseline versions carry untracked public maturity; a newly started lineage explicitly uses maturity0 under this versioned provisional policy. Completed legacy catalogue-project percentages remain work completion, separately from equipment maturity. Science grants generation access; refining within an available generation needs no new Science level.

A project chooses one of reactor capacity decrease, reactor supply increase or Industry decrease. Reactor supply is distinct from demand. Its cost is fixed at24000 internal Engineering units (40 displayed), adjusted once by the campaign research pace. Ordinary Engineering reserve/spending/receipts and one active target provide paid work; paused work retains progress. Managed project definitions appear only in the dedicated projection, preserving the 20 legacy cards.

All numeric tuning below is **proposed, versioned implementation policy**, rather than final owner balance:

- Maturity uses thousandths. A normal step is5points. The factor is1 through100, `(150-M)/50` from100 to150, and0 at150. Target gain, maturity gain and detractor magnitude use the starting parent's factor. A step below0.1points is inadmissible.
- Capacity/supply target quanta are8/9/10/11/12percent; Industry quanta are10/12.5/15/20/25percent. Detractor quanta are2/4/6/10/15percent. Weights are1/2/3/2/1.
- Apply the rational factor before integer quantization. Aggregate equal integer outcomes and reject zero/out-of-range deltas. There is no forced minimum increment. Each attribute stays within half to twice its frozen generation-root value, with a positive floor. Branching and naming do not recenter those bounds.
- An admissible goal has at least one clean and one one-detractor result. Every result improves the selected attribute. The category is sampled once at70percent clean /30percent one real detractor; maturity does not change those probabilities. A locally derived, domain-separated random stream leaves campaign RNG/allocation untouched.

## Actual service context

Each project freezes an owned published blueprint, installation, catalogue and power profiles. A default representative is selected deterministically; an explicit owned blueprint/revision may be requested. The counterfactual compiler changes only reactor Capacity, PowerSupply and Industry. Preserve actual profile allocations and outputs. A capacity target must lower compiled capacity used; an Industry target must lower compiled Industry; a supply target must raise actual available power in at least one profile. Extra reactor supply behind an unchanged saturated distribution limit is inadmissible. Feasible integer outcomes and the protected context determine preview ranges. No cross-unit score claims universal superiority.

The source and all outcome vectors remain immutable in experiment history. Each child inherits its actual parent's maturity and frozen generation bounds; siblings do not share a maturity pool. Practical integer/context exhaustion rejects before charging work.

## Persisted lifecycle and usable hardware

Start commits a durable experiment and normal Engineering target. Completing work atomically persists one result and draw identity as Pending before any decision. Reopening or reloading reads the same result.

- Accept retains/releases that exact result into current-access designer selection after actual support/readiness validation. It creates neither a published class revision nor a construction/refit order.
- Continue requires an explicit goal, retains the current result internally, and atomically starts a new normal paid project from that exact vector and maturity. An invalid continuation leaves the original pending result unchanged. An internal parent can be explicitly released later.
- Discard makes only a Pending result terminal/unavailable. Its spent work, result, ancestry and draw remain saved; it cannot later parent work, be accepted or be continued. There is no refund or reroll.
- Pause/Resume manipulate the existing single target. Closing a GUI modal submits no decision.

Release uses a separate managed authorization gate from the paid project's completion. An internally retained ancestor needed for a released child's frozen catalogue stays unavailable until separately released. The marker is administrative metadata, not an additional Engineering work charge or matured-project statistic. Old publications, queued orders and installed ships retain their frozen references.

Explicit compiler v5 derives support only for installed `component.refinement.*` reactor ancestry rooted in an existing supported mapping. Every other functional field, generation/family, mode, compatibility, material, credit and maintenance fact stays exact. New publication/construction uses actual compiled reactor values. Historical v4 support keeps its existing behavior; no global mapping is mutated.

## Transactions, replay and bounds

Commands require controlled actor, Planning phase, exact turn/revision and unique command identity. Transactions fork campaign authority, definitions and refinement state; only a fully validated candidate is published. GUI uses the existing worker/lease pattern and publishes a prepared frame through its controller; stale frames, abandoned workers and reordered results cannot commit.

The root stores at most64 experiments and1024 refinement commands, plus normal bounded Cycle state. Each refinement operation records the ordinary journal offset; list order is authoritative for multiple commands at one offset. Replay starts from the frozen source, interleaves those commands with the single ordinary journal, and compares the complete resulting root. Draws and outcomes are derived once at the recorded paid completion and must match the saved record. Explicit object visitors bound frozen blueprint contexts within the shared2million-node/64MiB root limits before copying/decoding. Old profile DTOs do not gain new fields.
