Use a new review-only slot such as `owner-early-20261014-a`; preserve all existing saves/artifacts. Distinguish manual input, automated UI event injection and owner-described task success.

Concept PNGs/browser renderings are not substitutes. No raw private save/enemy state belongs in public screenshots.

Proposed EARLY release bars (metrics, not gameplay formulas): every primary screen/action is reachable through visible named navigation in at most two deliberate selections; all six discipline summaries are simultaneously discoverable with no more than one in-panel scroll; Engineering has a direct named entry; primary transaction/modal actions are reachable without scrolling unrelated lists. At every target size there are **zero overlaps/clipped transaction summaries**, no disabled-looking active primary control, one visible selected page and clear actor/turn/phase. Extra wide space must benefit map/data rather than stretch buttons into paragraphs. Record actual scroll counts/time-to-find; do not mark pass based solely on presence in a visual tree.

For keyboard, record Tab/ShiftTab focus indication/order, activation, dropdown Enter/Escape, modal Confirm/Cancel/Escape according to the implemented semantics, and restoration of focus after closing. A failed injected key is **unverified/fail with cause undetermined**, not proof that hardware keys work. Mouse success cannot silently stand in for keyboard acceptance.
