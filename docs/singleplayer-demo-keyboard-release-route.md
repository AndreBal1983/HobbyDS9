# Demo keyboard release routing correction

19 October 2026. **CPU candidate; receiving and native correction checks pending.** Isolated branch `codex/demo-keyboard-release-route`, based on frozen R4 source `ba152554a2307cf389a621398066ae1a1d608baf` / [draft PR54](https://github.com/AndreBal1983/HobbyDS9/pull/54). The R4 package, its build checkout and owner saves are not changed by this branch.

R4 native acceptance observed Return starting the demo, then a later Return reaching the focused purchase confirmation without activating it. The passive log showed no focused child immediately after Start rebuilt the panel; later it recorded the focused confirmation's KeyDown with no raw or Submit action signal. That observer records UI KeyDown, not UI KeyUp or the private held latch. These observations support a release-routing gap but do not prove which release event the operating system/provider delivered.

The old release callback lived only on `UIDocument.rootVisualElement`. An unfocused release addressed to the panel visual tree is outside that document subtree. Start rebuilds `PanelSettings` while intentionally retaining the held latch, so a release outside the document could leave the later control suppressed. Clearing the latch on Build would instead allow an opening/confirming held key to act on a new modal.

The correction observes only KeyUp on the current panel's public `visualTree`. Document attach/detach and explicit unbinding replace/remove that subscription; repeated binding first unbinds. Held latches still survive Build and reset only through the existing release/focus-loss/disable paths. Button callbacks, original Submit duplicate suppression, epochs, disabled/detached guards, Tab, text fields/dropdowns, gameplay, save versions and default startup remain unchanged. No polling loop, provider changes, private focus access or global event dispatch is added.

Two additional receiving fixtures are authored, **not executed**: actual menu Return triggers Start/rebuild and leaves no focused child; an arranged public panel-root release then permits a later focused modal Return. The lifecycle fixture keeps a held press suppressed through obsolete-panel release, repeated bind/unbind and document detach/reattach, then accepts only a release observed on the current attached panel. The five prior keyboard fixtures retain the real-action and fallback held/modal protections. Arranged public UI events are not evidence of physical keyboard or automatic provider routing.
