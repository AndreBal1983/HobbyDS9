# Authored Sol main asteroid belt

18 November 2026. This source implements a separate authored-Sol-belt campaign edition. Existing richness-v1 start/load behavior stays unchanged. GUI activation, layout and native visual acceptance remain separate gates; targeted-refinement mechanics are not part of this edition.

NASA's [Dawn FAQ](https://science.nasa.gov/mission/dawn/faq/) answers the asteroid-spacing question dated 13 June 2010 using an **approximate 2.2–3.2 AU** belt region. The JPL answer explains that the actual distribution is nonuniform and the belt is mostly empty. [belt.json](belt.json) records the source, dated question, retrieval date, units and approximation. The stored 2200–3200 milli-AU band preserves that source precision; it does not establish exact orbital edges, density, mineable stock, hazard or an ephemeris.

`AuthoredSolBeltData.Create(FrozenColonisationPlanetsDto inventory, string mapSeed)` returns one detached `SystemAsteroidBeltDto` or null. It requires unique, coherent physical and definition/body bindings for `planet.sol`, `planet.mars` and `planet.jupiter`, then uses their actual mapped system ID. It never infers Sol from a display name, faction label or hardcoded generated ID. Feature identity is `belt.authored.sol.asteroid.v1`; the visual seed hashes the helper version, map seed, mapped system ID and feature identity in a separate visual-scatter domain. It neither mutates the inventory nor consumes campaign RNG/allocation. No body, deposit, colony or controller row is added.

Integration must preserve existing richness-v1 genesis and saves, admitting this additional authored feature only under the new campaign/profile/save identity. The sourced band is **1000 milli-AU wide**, beyond the old procedural maximum of 999; do not round it to fit. New-edition validation and GUI layout must explicitly admit the authored record while keeping old procedural limits. Actor disclosure must use the existing lawful system-presence/retained-arrival path. GUI should place the band through its same compressed ordered Sol AU mapping between Mars and Jupiter, not the old unrelated `12 + milliAu*.004` mapping. New-campaign and saved-feature reload tests plus native rendering remain integration gates.

## Versioned receiving contract

`CampaignColonisationCycleApplication.CreateAuthoredSolPackage(growth)` and the frontend `AuthoredSolPlaytestOptions.CreatePackage(growth)` create package format 3/profile `generated-colonisation-authored-sol-belt-package-v1`. Existing `StartCycleGame` and `LoadCycleSave` accept its explicit typed carrier. Complete saves use `CampaignAuthoredSolSaveDto`, **Format16**, profile `generated-colonisation-authored-sol-belt-v1`, `GenerationVersion=system-richness-sol-belt-v2`. The new package and save are known sealed peers of the old Cycle/richness carriers; older saved classes gain no fields and unknown subtypes remain rejected. No JSON type-name dispatch is enabled.

Physical planet generation and non-home belts use the exact unchanged richness-v1 recipe. The one new authored row is appended using the real frozen Sol association; no body, resource, colony, ownership, yield, motion or campaign RNG change. A source without the required Sol identities rejects rather than manufacturing a solar system. The distinct package hash/profile binds the new feature. Missing, altered, duplicated, downgraded and cross-edition roots reject through strict shape/preflight and complete replay. Old Format15/v1 keeps its prior no-home-belts behavior and save shape, including its 999-milli-AU procedural thickness limit.

`CaptureKnownAstronomy(actor)` returns the usual lawful actor snapshot with **`SystemBeltGeneration=system-richness-sol-belt-v2`** for this edition. The authored record uses `RadiusUnit=milli-au-authored-reference-v1`; procedural records keep their existing unit marker. Own Sol coverage reveals the authored belt immediately; foreign/unknown systems do not gain disclosure. Save/reload retains the exact row and visual seed. The existing 1000-belt/6040-planet/2M-visit/64MiB ceilings stay unchanged.

GUI must select `AuthoredSolPlaytestOptions` explicitly and use its **`SaveDirectorySuffix=-engineering20-sol08-authoredbelt1`**. Do not append the row into existing v1 saves or reuse their directory. The frontend scene filter must admit the exact new generation header and sourced authored-row band; existing v1 filters must remain strict. No Entry/menu/Panel/renderer file is changed by this backend delivery.
