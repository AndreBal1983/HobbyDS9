## Brief and receiving boundary

The System brief is a large readable selected globe, recognisable Earth/Mars geography, a useful terminator, restrained Earth limb and warm textured stellar core with a bounded corona. The complete nine-body Sol reference library supports lawful disclosed presentations; it is not a campaign snapshot and assigns no hidden planet IDs. The overview composition and orbit spacing are illustrative, not astronomical scale. Decorative star texture is seeded original artwork, not a star catalogue. The current dedicated selected-globe camera and exact `planet.sol`/`planet.mars` selection should remain the integration seam.

The hull brief is a complete inspectable exterior with pearl/slate metal, restrained warm windows and blue/red energy details. The cruiser uses a broad saucer, engineering body and paired nacelles; the escort uses a compact low body and integrated flank pods. These are **new original procedural candidates** for exact `hull.galaxy-cruiser.v1` and `hull.defiant-combat.v1`. They are not the previously approved, unreceived external replacement models, not replicas of their mesh topology, and not certified canonical designs. Owner visual approval remains open. `hull.constitution-explorer.v1` retains existing original art. No full-fleet redesign or component/socket system is implied.

## Import contract

Authoring uses metres, +Z up, hull bow -Y. GLB uses metres, +Y up, bow +Z; FBX exports `axis_forward=-Z`, `axis_up=Y`, scale 1. Preserve importer root TRS and verify actual forward/up in receiving. Do not add an unexplained scale 100 correction. Planet surface mesh radius is exactly one, centred at zero; apply current presentation radius outside it. Hulls are centred on geometric bounds, 620 m and 170 m in the existing nominal art-length contract. Those lengths are visual scale only, not new simulation values.

Use the **FBX** route for ordinary Unity import and remap materials explicitly; GLB is self-contained interchange/inspection, not a claim that a glTF Unity importer is installed. UV0 and normals are authored; import normals and tangents as appropriate for receiving. No normal maps, lightmaps, rig, animation, sockets or colliders are supplied. No baked lighting is in the surface maps. Do not infer gameplay mounts from windows, intake shapes or sensor details.

Start receiving with mesh compression off, no generated colliders, no animation/rig import and no UV regeneration. Keep Read/Write enabled if adapting the current `ReviewSolStage.DeliveredMesh` path: that contract inspects CPU mesh arrays; disable readability only after an explicit receiving change removes that requirement. Use Repeat U / Clamp V on planetary maps and retain sRGB for albedo. Hull primitive UVs may overlap and are suitable for the supplied factor-only materials; they are not a unique paint atlas or lightmap unwrap.

URP mapping: Principled Base Color → Lit Base Map/tint (sRGB); Metallic factor → Metallic; Smoothness = 1 − Roughness; emission colour × strength → HDR Emission, with emission enabled. Hull material factors are sufficient without textures. Surface material is opaque, roughness .82; Sun additionally emits its map at strength 1. Earth atmosphere is optional **separate** radius-1.018 mesh and is disabled by default: its exported opaque placeholder must be replaced by a restrained Fresnel transparent material before showing it. The Blender studio atmosphere shader does not export through standard glTF. Never apply the Earth atmosphere to Mars. Saturn bands need Cull Off/two-sided shading. Orbit bands are nonpickable; substitute an antialiased screen-space line when the thin mesh aliases. Corona uses the original RGBA texture on a camera-facing plane, transparent alpha with emission, no shadow casting, ZWrite Off; hide it for a planet portrait. Do not require bloom to read the core. Stars are a decorative background only.

Each pack includes `material-recipes.json`, extracted from the actual exported glTF factors. The system pack additionally supplies [PlanetLimb shader source](system-v1/Shaders/PlanetLimb01.shader) with front-face culling, transparent falloff, depth test and no depth/shadow write. This optional shader has **not** been compiled or rendered in Unity. Its source uses the same URP Core transform helpers as the existing project shaders; native receiving must still verify platform compilation, depth order and appearance. Do not enable the shell with its placeholder material while awaiting that check. Suggested shader GUID is in `receiving.json`.

LOD suggestion: surface LOD0 above 256 projected pixels, LOD1 64–256, LOD2 below 64; receiving should tune actual error/cost. A body pick uses a sphere; orbit/corona/atmosphere never pick. A hull preview normally needs no collider; if selection requires one use a conservative bounds box or a small compound of boxes. Do not create gameplay collision from these exteriors. Large maps should be streamed/lazily loaded for selected bodies, not replicated per LOD/material instance.

## Budgets and acceptance

Surface caps: 10,000 triangles per exported asset, 2K maximum albedo, 1K overview import, one opaque surface material. Actual 96×48, 48×24 and 24×12 spheres are 9,024 / 2,208 / 528 triangles. Saturn bands 1,152; orbit 512; atmosphere 2,208; corona 2. Reuse one copy of each map across all LODs. Nine 2048×1024 maps cost about 24 MiB with full BC7 mip chains, or 96 MiB uncompressed RGBA8; importing all at 1024×512 reduces that to about 6 / 24 MiB respectively. These are texture allocation estimates, not measured Unity residency; PNG/JPEG file sizes are not VRAM. Accent alpha maps have separate dimensions in receiving inventory. Hull caps: 35,000 LOD0 triangles, ≤8 material slots, no texture allocation for their factor-only materials; measured actual counts are in their manifest. Only one selected hull should be loaded by the existing preview lifetime owner. Do not allocate render targets per row.

Use a 1.5 MiB GPU geometry allowance per selected LOD0 hull (positions/normals/UVs/indices with importer split overhead), ≤8 renderer material passes, and no unique hull texture allocation. These are receiving caps, not GPU profiler results. The 1K overview cap above applies when receiving an overview-only texture variant; the delivered 2K source can support selected portraits. A 2K imported texture still occupies its full allocation unless native streaming/lazy loading is actually configured and verified. Mip sampling alone does not prove lower residency.

Portraits are 720² proof renders; the live portrait target remains bounded by the current runtime contract. The overview proof is 1440×640. `*_studio` images use Blender Cycles CPU/AgX lighting; `*_direct_light_reference`, hull top/side views and source bounds expose shape/albedo without a claim of URP parity. All previews render the delivered new geometry. They are not painted mockups, runtime screenshots, or owner acceptance. The studio composition is reproducible from `SystemPresentation.blend`; its atmosphere uses a studio shader requiring explicit URP receiving.

Receiving must verify actual Unity normals/UVs and transforms, material remaps/alpha/emission, complete framing and ring visibility, Earth/Mars identity, selected-world change/disposal, lazy preview lifetime, no hidden-body disclosure, supported sizes and per-frame cost. Only then compare actual native screenshots with the director and owner. No gameplay tests are needed for this isolated asset delivery because no gameplay behaviour changes.
