13 November 2026. Proposed original assets, native receiving and owner acceptance open. This is an additive continuation of [the first pack](README.md). No v1 binary/source packet, existing Unity resource, metadata, gameplay mapping or save is changed.

## One-slot hull runtime slice

[hulls-runtime-v2](hulls-runtime-v2/manifest.json) refines the **same** original cruiser and escort candidates. All three LODs retain their v1 triangle geometry, normals, metre bounds and centred pivots. The former 8/8/7 material slots become **one opaque `Material_0` submesh per model**. A 512×256 atlas per channel retains the original roles/colours/material factors, with a restrained original panel pattern in the pearl hull tile. Each of eight tiles has an eight-pixel gutter. No borrowed image pixels, new hull, new variant, new equipment or capability is introduced.

Four PNGs per hull: `BaseColor` (sRGB, A=1), `ORM` (linear R=1 unused / G=roughness / B=metallic / A=1), `Normal` (linear conventional flat tangent-space +Z, +Y convention; no invented detail), `Emission` (sRGB, decoded linear RGB × HDR2). Full mipmapped RGBA8 allocation is approximately 2.67 MiB per hull for all four maps; BC7/BC5 at 8 bpp is approximately 0.67 MiB. File compression is not residency. Source colours are linear factors encoded explicitly to sRGB bytes. Native import must verify actual formats/mips and atlas bleeding at small sizes; gutters support useful mips but do not eliminate eventual low-mip tile mixing.

`material-contract.json` is the exact slot, tile, factor, channel and shader-property contract. Bind `_BaseMap`, `_MetallicRoughnessMap`, `_BumpMap`, `_EmissionMap`; `_BaseColor=(1,1,1,1)`, `_Metallic=1`, `_UseMetallicRoughnessMap=1`, `_UseNormalMap=1`, `_BumpScale=1`, `_EmissionColor=(2,2,2,1)`. Tangents are exported; inspect their native import before enabling the normal path. Geometry is opaque with back-face culling, no coat/transmission/bloom requirement. Material/texture leases and disposal stay with the current preview owner; borrowed Resources textures must not be destroyed.

This satisfies the **shape** of the current Defiant one-submesh path; it does not silently install into it. GUI must receive **new candidate resource paths and original-work credits**, then explicitly load the four named textures, including emission. The current binder's old three-image prefix and source credit cannot remain attached to the new art. Generic `StudioMaterials` currently omits copying packed ORM, so that path requires a deliberate copy/binding of `_MetallicRoughnessMap` and `_UseMetallicRoughnessMap`; exporting a packed map alone does not enable it. Galaxy currently uses a different multipart factory and needs a separately admitted exact candidate route. Keep its existing fallback/credits until then. Do not select these models by class-name substring, role, size or inferred enemy hull version.

That source already resolves the legacy binder mismatch and is queued for native QA. Keep that batch unchanged. The one-slot atlas pack is an optional alternative for later measured comparison: it trades fewer material slots for texture allocation/sampling and is not automatically faster or a mandatory replacement. Its ORM channel layout targets the current PreviewStudio/glTF path; other shaders require their own explicit channel mapping.

These remain **new original procedural candidates** for `hull.galaxy-cruiser.v1` / `hull.defiant-combat.v1`, not the unreceived approved external replacement files. Activity/Construction preview and Fleet's civilization+design route are different seams; this pack does not extend either mapping automatically. Fixed exteriors still have no authoritative equipment/socket map.

Actual Blender/PBR proofs and 512×320 **CPU formula proxies** are in the [gallery](hulls-runtime-v2/gallery.html). Proxies use the current `PreviewStudio.shader` formula and the activity camera defaults (37.57° yaw,26° pitch, projected bounds,1.12 margin), with the exact shader source hash in the material contract. They assume an X-reflected FBX receiver basis and do not establish Unity importer transforms, colour-management parity, shader pixels, native workflow or performance. Do not substitute them for QA's native captures.

## Globe receiving witness, not a UV replacement

[system-receiving-witness-v2](system-receiving-witness-v2/manifest.json) preserves the **same v1 Earth/Mars positions and UVs**. It adds geometry-only FBX/GLB witnesses, a labelled original equirectangular QA texture and explicit exported-space evidence. It admits **no runtime binding** and recommends **no replacement of PR106's received globes**.

Raw right-handed glTF positions have U0 at −X,U.25 at +Z. With X reflection the same UVs satisfy the receiver's stated +X/+Z longitude basis to within about7e−8. This is a coordinate-convention diagnostic, not evidence of a native defect. Unity documents conversion into its left-handed axis system, performed in geometry or importer/root conversion according to settings; see [ModelImporter.bakeAxisConversion](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/modelimporter/bakeaxisconversion). Only the full actual imported hierarchy can establish the game's final basis.

QA can apply the witness texture temporarily to the **already received** Earth/Mars mesh in an isolated graphics test, inspect U0/+X,U.25/+Z,north V1,south V0, readable labels, seam continuity, normals and full unit radius, then restore the production property block. Preserve Repeat U/Clamp V, readable mesh validation and current target/portrait/disclosure controls. The named X-reflection Blender views predict one receiver convention; they are not Unity captures. Earth/Mars maps here are unchanged Solar System Scope / INOVE CC BY4.0 copies for source proofs, not new runtime texture admissions. Their original credit/source hashes are retained.
